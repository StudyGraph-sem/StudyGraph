# StudyGraph — описание структуры базы данных

**СУБД:** PostgreSQL   
**Состав:** 8 таблиц — `users`, `subjects`, `roadmaps`, `topics`, `topic_dependencies`, `notes`, `file_assets`, `note_files`.

## 1. Общая модель

Пользователь создаёт **предметы**. Один предмет может содержать несколько **роадмапов** — альтернативных вариантов программы. Каждый роадмап представляет собой граф из **тем** (`topics`) и направленных **зависимостей** (`topic_dependencies`). К темам добавляются **заметки** (`notes`); к заметкам можно прикреплять любое число файлов из S3 через `note_files`.

## 2. Сущности и атрибуты

Обозначения: **PK** — первичный ключ; **FK** — внешний ключ; **NULL** — отсутствие значения разрешено; **Нет** — поле обязательно.

### 2.1. `users` — пользователи

Хранит учётные записи и роли. Используется для авторизации через JWT и определения владельцев данных.

| Атрибут | Тип | NULL | Назначение |
|---|---|---|---|
| `id` | `UUID`, PK | Нет | Уникальный идентификатор, на который ссылаются другие таблицы. |
| `name` | `VARCHAR(120)` | Нет | Отображаемое имя; ограничение длины. |
| `email` | `VARCHAR(254)` | Нет | Адрес для входа; должен быть уникальным. |
| `password_hash` | `TEXT` | Нет | Хеш пароля; переменная длина зависит от алгоритма. |
| `role` | `user_role` | Нет | PostgreSQL enum: `student` или `admin`. |

Роли фиксированы, поэтому таблица `roles` не нужна. JWT не сохраняются в этой таблице.

### 2.2. `subjects` — предметы

Объединяет несколько вариантов изучения одной дисциплины и задаёт правила доступа к ним.

| Атрибут | Тип | NULL | Назначение |
|---|---|---|---|
| `id` | `UUID`, PK | Нет | Идентификатор предмета. |
| `owner_user_id` | `UUID`, FK | Нет | Ссылка на владельца в `users`. |
| `title` | `VARCHAR(200)` | Нет | Название дисциплины. |
| `description` | `TEXT` | Да | Необязательное описание произвольной длины. |
| `visibility` | `subject_visibility` | Нет | Enum: `private`, `public`, `unlisted`. |
| `share_token` | `UUID`, UNIQUE | Да | Секретный идентификатор ссылки для `unlisted`; в остальных режимах не нужен. |

Режимы: `private` — доступ владельцу; `public` — публичный просмотр; `unlisted` — просмотр по специальной ссылке. Правило доступа распространяется на вложенные роадмапы, темы, заметки и доступные через них файлы. Возможность *редактирования* остаётся у владельца или уполномоченного администратора.

### 2.3. `roadmaps` — варианты учебной программы

Отдельная сущность нужна, потому что **один предмет может иметь несколько независимых графов**.

| Атрибут | Тип | NULL | Назначение |
|---|---|---|---|
| `id` | `UUID`, PK | Нет | Идентификатор роадмапа. |
| `subject_id` | `UUID`, FK | Нет | Предмет, которому принадлежит роадмап. |
| `title` | `VARCHAR(200)` | Нет | Название варианта программы. |
| `description` | `TEXT` | Да | Необязательное описание особенностей программы. |

Например, для «Баз данных» возможны роадмапы «Университетский курс» и «Подготовка к экзамену». Их темы и прогресс независимы.

### 2.4. `topics` — темы (вершины графа)

Хранит содержание темы, её статус, вес при расчёте прогресса и положение на интерактивной карте.

| Атрибут | Тип | NULL | Назначение |
|---|---|---|---|
| `id` | `UUID`, PK | Нет | Идентификатор вершины. |
| `roadmap_id` | `UUID`, FK | Нет | Роадмап, в котором расположена тема. |
| `title` | `VARCHAR(200)` | Нет | Название темы. |
| `description` | `TEXT` | Да | Необязательное содержание/пояснение. |
| `study_status` | `VARCHAR(20)` | Нет | `not_started`, `in_progress` или `completed`. |
| `importance_weight` | `NUMERIC(8,2)` | Нет | Положительный десятичный вес для расчёта прогресса; точность до сотых. |
| `position_x` | `NUMERIC(12,3)` | Да | Координата X в редакторе графа. |
| `position_y` | `NUMERIC(12,3)` | Да | Координата Y; обе координаты могут отсутствовать до размещения узла. |

`blocked` **не сохраняется** как самостоятельный статус: блокировку рассчитывают по незавершённым предварительным темам. Положение узлов сохраняется для Cytoscape.js. Отдельного времени завершения темы в итоговой схеме **нет**.

### 2.5. `topic_dependencies` — зависимости тем (рёбра графа)

Представляет направленную зависимость «для изучения темы B сначала нужна тема A».

| Атрибут | Тип | NULL | Назначение |
|---|---|---|---|
| `roadmap_id` | `UUID` | Нет | Общий роадмап обеих тем; участвует в составных FK. |
| `topic_id` | `UUID`, FK, PK | Нет | **Зависимая** тема (B). |
| `prerequisite_topic_id` | `UUID`, FK, PK | Нет | **Предварительная** тема (A). |

- **Составной PK** `(topic_id, prerequisite_topic_id)` не позволяет добавить одно ребро дважды; отдельный `id` не нужен.
- **Два составных FK** `(roadmap_id, topic_id)` и `(roadmap_id, prerequisite_topic_id)` → `topics(roadmap_id, id)` гарантируют, что связь соединяет темы **одного роадмапа**. Поэтому `roadmap_id` присутствует и здесь, хотя его можно определить через тему.
- Запрещена прямая самозависимость (`topic_id <> prerequisite_topic_id`). Проверку более длинных циклов (A → B → C → A) необходимо реализовать отдельно в серверной логике или БД.

Таким образом, две линии между `topics` и `topic_dependencies` на диаграмме — **две роли одной таблицы `topics`**, а не две одинаковые связи.

### 2.6. `notes` — заметки к темам

Одна тема может иметь много заметок; заметка может существовать без файлов.

| Атрибут | Тип | NULL | Назначение |
|---|---|---|---|
| `id` | `UUID`, PK | Нет | Идентификатор заметки. |
| `topic_id` | `UUID`, FK | Нет | Тема, к которой относится заметка. |
| `title` | `VARCHAR(255)` | Нет | Обязательное название. |
| `description` | `TEXT` | Да | Необязательный текст заметки. |

Прикреплённые файлы не перечисляются в одном поле: их связывает таблица `note_files`.

### 2.7. `file_assets` — файлы в объектном хранилище

Хранит **метаданные** загруженных файлов; содержимое находится в S3-совместимом хранилище.

| Атрибут | Тип | NULL | Назначение |
|---|---|---|---|
| `id` | `UUID`, PK | Нет | Идентификатор файла в приложении. |
| `owner_user_id` | `UUID`, FK | Нет | Пользователь, владеющий файлом. |
| `bucket_name` | `VARCHAR(255)` | Нет | Название S3-бакета. |
| `object_key` | `VARCHAR(1024)` | Нет | Ключ объекта внутри бакета; допускает длинный путь. |
| `original_name` | `VARCHAR(255)` | Нет | Исходное имя файла для интерфейса/скачивания. |
| `content_type` | `VARCHAR(255)` | Да | MIME-тип; может быть неизвестен. |
| `size_bytes` | `BIGINT` | Нет | Размер файла в байтах; тип рассчитан на большие значения. |
| `upload_status` | `VARCHAR(20)` | Нет | Состояние загрузки: `pending`, `ready`, `failed`. |

`upload_status` нужен, поскольку запись в PostgreSQL и загрузка объекта в S3 — две разные операции. Пара `(bucket_name, object_key)` должна быть уникальной. В итоговой схеме у файлов **нет** полей `created_at` и `uploaded_at`.

### 2.8. `note_files` — прикрепления файлов к заметкам

Промежуточная сущность для отношения **M:N**: у заметки сколько угодно файлов, а файл может использоваться в нескольких заметках.

| Атрибут | Тип | NULL | Назначение |
|---|---|---|---|
| `note_id` | `UUID`, FK, PK | Нет | Заметка. |
| `file_asset_id` | `UUID`, FK, PK | Нет | Прикреплённый файл. |

Составной PK `(note_id, file_asset_id)` запрещает повторно прикреплять один файл к одной и той же заметке. Отдельный UUID не требуется.

## 3. Все связи

| Родительская таблица | Дочерняя таблица | Кардинальность | Основание |
|---|---|---|---|
| `users` | `subjects` | 1:N | У пользователя несколько предметов. |
| `users` | `file_assets` | 1:N | Пользователь владеет несколькими файлами. |
| `subjects` | `roadmaps` | 1:N | У предмета несколько вариантов программы. |
| `roadmaps` | `topics` | 1:N | Роадмап состоит из тем. |
| `topics` | `topic_dependencies` | 1:N × 2 | Тема может зависеть от нескольких тем и быть prerequisite для нескольких других. |
| `topics` | `notes` | 1:N | У темы несколько заметок. |
| `notes` | `note_files` | 1:N | Заметка имеет набор прикреплений. |
| `file_assets` | `note_files` | 1:N | Один файл может использоваться в нескольких заметках. |

Две связи `topics` ↔ `topic_dependencies` представляют **направленную рекурсивную M:N-связь**; вместе `notes` ↔ `note_files` ↔ `file_assets` представляют обычную **M:N-связь**.
