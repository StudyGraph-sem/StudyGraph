# Vision проекта StudyGraph

## 1. Общая информация

**Название проекта:** StudyGraph  
**Тип продукта:** Веб-приложение для персонального управления учебными материалами, планирования обучения и визуализации структуры знаний.

**StudyGraph** — информационная система, предназначенная для организации учебного процесса с помощью интерактивного графа знаний. Приложение позволяет студентам формировать индивидуальную структуру изучаемых дисциплин, отслеживать освоение тем, управлять учебными материалами и контролировать выполнение учебных задач.

В основе продукта лежит представление учебной дисциплины в виде графа, вершинами которого являются отдельные темы, а направленными рёбрами — зависимости между ними. Такой подход позволяет наглядно отображать последовательность изучения материала, выявлять необходимые предварительные знания и определять наиболее значимые этапы подготовки.

Пользователь может самостоятельно создавать и редактировать граф дисциплины, прикреплять к темам конспекты, файлы, ссылки и заметки, фиксировать текущий прогресс обучения и планировать выполнение домашних заданий.

В перспективе StudyGraph предусматривает формирование общей библиотеки учебных роадмапов, в которой пользователи смогут публиковать собственные структуры дисциплин, использовать материалы других участников и адаптировать существующие графы под индивидуальные образовательные программы.

Таким образом, StudyGraph объединяет возможности персональной базы знаний, инструмента визуального планирования обучения и системы контроля учебного прогресса.

## 2. Назначение системы

Назначение StudyGraph заключается в решении проблемы разрозненного хранения учебной информации и недостаточной наглядности образовательного процесса.

В процессе обучения студенты используют множество независимых инструментов: файловые хранилища, электронные конспекты, заметки, календари и списки задач. Информация об учебных дисциплинах распределяется между различными источниками, что затрудняет её систематизацию, поиск и повторное использование.

Кроме того, традиционные способы организации учебных материалов не отражают логические связи между изучаемыми темами. В результате студенту бывает сложно определить, какие знания необходимы для освоения следующей темы, какие разделы уже изучены и какие пробелы препятствуют дальнейшему обучению.

Дополнительной проблемой является отсутствие единого представления учебного прогресса, учитывающего не только количество завершённых тем, но и их взаимосвязи и значимость в структуре дисциплины.

StudyGraph предназначен для устранения перечисленных проблем путём объединения учебных материалов, зависимостей между темами, информации о прогрессе и учебных задач в рамках одной системы.

Использование приложения должно позволить студенту:

- систематизировать материалы по дисциплинам и отдельным темам;
- понимать логическую последовательность изучения учебного материала;
- выявлять темы, освоение которых зависит от предварительных знаний;
- отслеживать текущий прогресс и определять оставшийся объём обучения;
- контролировать сроки выполнения домашних заданий и других учебных задач;
- эффективнее планировать самостоятельную подготовку и повторение материала.

## 3. Пользователи системы

**Основной целевой аудиторией** StudyGraph являются студенты высших и средних профессиональных учебных заведений, которым необходимо самостоятельно организовывать изучение дисциплин, хранить учебные материалы и контролировать образовательный прогресс.

В рамках системы предусматриваются следующие категории пользователей:

### 3.1. Неавторизованный пользователь

Посетитель веб-приложения, которому доступно ознакомление с общими возможностями системы, регистрация и авторизация.

В перспективе неавторизованным пользователям может предоставляться возможность просмотра публичных учебных роадмапов.

### 3.2. Авторизованный пользователь (студент)

Основной пользователь системы, обладающий доступом к персональному образовательному пространству.

Студент может создавать и редактировать собственные дисциплины, формировать графы учебных тем, управлять зависимостями между ними, добавлять материалы, изменять состояние изучения тем и отслеживать прогресс.

Также пользователь может создавать учебные задачи, устанавливать сроки их выполнения и получать напоминания о приближающихся дедлайнах, в том числе по электронной почте.

В перспективе студент сможет публиковать собственные роадмапы, использовать опубликованные другими пользователями структуры дисциплин и создавать их независимые копии для дальнейшего редактирования.

### 3.3. Администратор системы

Пользователь, отвечающий за поддержание работоспособности системы, управление учётными записями и контроль соблюдения правил использования сервиса.

При реализации публичной библиотеки администратору могут быть предоставлены дополнительные инструменты модерации опубликованных роадмапов и материалов.

## 4. Цели проекта

**Основная цель проекта** — разработать веб-приложение, обеспечивающее централизованное хранение и структурирование учебных материалов, визуализацию зависимостей между темами и управление индивидуальным процессом обучения.

Для достижения основной цели необходимо решить следующие задачи:

### 4.1. Организация персонального образовательного пространства

Реализовать возможность создания, просмотра, редактирования и удаления учебных дисциплин. Каждая дисциплина должна объединять связанные с ней темы, материалы, учебные задачи и информацию о прогрессе.

### 4.2. Визуализация структуры дисциплин

Разработать интерактивный редактор учебных роадмапов, позволяющий создавать темы и устанавливать направленные зависимости между ними.

Система должна обеспечивать корректность структуры графа, предотвращая образование циклических зависимостей, и предоставлять наглядное отображение последовательности изучения материала.

### 4.3. Управление процессом изучения тем

Предоставить пользователю возможность фиксировать состояние изучения каждой темы, включая статусы «Не пройдено», «В процессе» и «Пройдено».

При наличии незавершённых обязательных предварительных тем система должна автоматически определять недоступные для последовательного изучения разделы и визуально обозначать их как заблокированные.

Изменение состояния тем должно отражаться на интерактивном графе и учитываться при расчёте прогресса дисциплины.

### 4.4. Централизованное управление учебными материалами

Обеспечить возможность прикрепления к отдельным темам файлов, ссылок и текстовых заметок.

Пользователь должен иметь возможность просматривать, добавлять и удалять связанные с темами материалы в рамках единого интерфейса.

### 4.5. Планирование и контроль учебных задач

Реализовать механизм создания домашних заданий, докладов и других учебных задач с возможностью указания сроков выполнения и привязки к соответствующим темам.

Предусмотреть уведомления о приближающихся сроках выполнения задач, включая отправку напоминаний по электронной почте.

### 4.6. Анализ образовательного прогресса

Разработать механизм расчёта прогресса изучения дисциплины с учётом структуры графа и значимости отдельных тем.

Предусмотреть определение критического пути изучения — последовательности взаимосвязанных тем, освоение которых наиболее существенно для завершения образовательного маршрута.

На основе результатов анализа предоставлять пользователю информацию об освоенных разделах, оставшихся темах и факторах, препятствующих дальнейшему продвижению.

### 4.7. Обеспечение удобства и доступности системы

Разработать понятный веб-интерфейс, позволяющий управлять учебными материалами и взаимодействовать с графом без необходимости владения специальными техническими знаниями.

Обеспечить разграничение доступа к персональным данным и пользовательским материалам.

### 4.8. Создание основы для дальнейшего развития

Предусмотреть возможность расширения системы следующими функциями:

- публичная библиотека учебных роадмапов с возможностью копирования и адаптации;
- специальный режим подготовки к экзамену, отображающий оставшиеся темы и контрольный список задач;
- интеллектуальное планирование повторения изученного материала;
- поиск по содержимому прикреплённых конспектов с визуальным выделением соответствующих тем;
- экспорт графа учебной дисциплины в PDF.

**Ожидаемый результат проекта** — работоспособное веб-приложение, в котором студент может самостоятельно организовать изучение дисциплины, визуально отслеживать последовательность освоения тем, хранить связанные с ними материалы и планировать выполнение учебных задач в рамках единого персонального образовательного пространства.

## 5. Технологический стек

Ниже представлен предполагаемый технологический стек проекта. Часть технологий относится к основному функционалу, а часть рассматривается для оптимизации или последующего расширения системы.

| Технология | Назначение |
|---|---|
| **C# / ASP.NET Core Web API** | Разработка серверной части приложения, REST API и бизнес-логики. |
| **Entity Framework Core** | Объектно-реляционное отображение (ORM), доступ к данным и управление миграциями базы данных. |
| **PostgreSQL** | Основная реляционная база данных для хранения пользователей, дисциплин, тем, зависимостей, учебных задач, статусов и метаданных материалов. |
| **TypeScript + React / Vue** | Разработка интерактивного пользовательского интерфейса веб-приложения. |
| **Cytoscape.js** | Визуализация графов учебных дисциплин, интерактивное редактирование вершин и связей, отображение статусов тем. |
| **S3-совместимое объектное хранилище** | Хранение загруженных конспектов, документов и других файлов; в базе данных сохраняются их метаданные и связи с темами. |
| **Hangfire** | Выполнение фоновых и периодических задач, включая проверку дедлайнов и запуск отправки напоминаний. |
| **MailKit + SMTP** | Формирование SMTP-клиента и отправка email-уведомлений о приближающихся дедлайнах и других событиях; требуется доступ к SMTP-серверу. |
| **Docker / Docker Compose** | Контейнеризация сервисов и воспроизводимый запуск приложения и его зависимостей в среде разработки. |
| **Redis** | Кеширование и хранение временных данных при возникновении соответствующей потребности в производительности. |
| **Elasticsearch / OpenSearch** | Полнотекстовый поиск по содержимому конспектов и материалов; выбор конкретного поискового движка откладывается до реализации этой функции. |

**Примечание:** специализированная NoSQL-база данных не предусматривается в текущем стеке. Граф тем и их зависимостей планируется хранить в PostgreSQL. Для предотвращения циклов и анализа последовательности изучения будут применяться алгоритмы работы с ориентированным графом на уровне бизнес-логики приложения.
