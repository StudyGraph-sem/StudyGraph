# Frontend Structure Guide

Памятка: куда добавлять код клиентской части StudyGraph.
Корень клиента — `frontend/`. Пути ниже указаны относительно этой папки.
Используется Vue + TypeScript, Vite, Vue Router и Pinia.

Сейчас клиент содержит шаблонную страницу App.vue, пустой список маршрутов, демонстрационный store counter и тест страницы. Страницы авторизации, задачи, диаграммы и запросы к API ещё не реализованы. Каталоги components, views, api и types ниже — рекомендуемые места для нового кода; создавай их по необходимости.

## Хочешь изменить запуск приложения?

`src/main.ts` создаёт Vue-приложение, подключает Pinia и Router и монтирует App.vue в контейнер из `index.html`.
`src/App.vue` — корневой компонент: здесь удобно размещать общий каркас страницы и RouterView. Бизнес-логику отдельных страниц выноси в соответствующие компоненты.

## Хочешь добавить страницу?

1. Создай компонент в `src/views/`: например, `LoginView.vue`, `RegisterView.vue`, `DashboardView.vue` или `StudyTasksView.vue`.
2. Добавь маршрут в `src/router/index.ts`.
3. Добавь `<RouterView />` в App.vue, чтобы страницы маршрутов отображались. Сейчас его там нет.

Для переходов используй RouterLink. При публикации приложения сервер должен поддерживать возврат index.html для клиентских маршрутов, поскольку используется createWebHistory.

## Хочешь добавить переиспользуемый элемент?

Создай компонент в `src/components/`: например, `StudyTaskCard.vue`, `ProgressChart.vue` или `DeadlineBadge.vue`. Данные передавай через props, события об изменениях — через emits.

Компонент .vue обычно содержит `<script setup lang="ts">`, `<template>` и `<style scoped>`. Не привязывай общий компонент к конкретной странице без необходимости.

## Хочешь добавить состояние пользователя или прогресса?

Создай Pinia store в `src/stores/`: например, `auth.ts`, `progress.ts` или `studyTasks.ts`. Pinia уже подключена в main.ts.

Общее состояние нужно, когда его используют несколько частей приложения. Состояние формы или открытого диалога обычно достаточно хранить локально через ref/reactive. `counter.ts` — демонстрационный пример, который можно удалить, если он нигде не используется.

## Хочешь отправить запрос к серверу?

Создай модуль в `src/api/`: например, `auth.ts`, `studyTasks.ts` или `progress.ts`. Общую настройку fetch, обработку ошибок и формат запросов можно вынести в `src/api/client.ts`. HTTP-запросы не стоит дублировать в нескольких компонентах.

Сейчас proxy в Vite и CORS на сервере не настроены. Для подключения клиента согласуй адрес API и выбери proxy разработки либо настрой CORS на backend. Если используешь префикс /api, согласуй его с реальными маршрутами сервера. Настройки proxy Vite не заменяют настройку сервера при публикации.

Переменные VITE_* попадают в клиентскую сборку: пароли БД, ключ подписи JWT и другие секреты туда помещать нельзя.

## Хочешь описать данные API?

Размещай общие типы в `src/types/`: например, `StudyTask.ts`, `ProgressReport.ts` и `AuthResponse.ts`. Поля должны соответствовать DTO backend, включая nullable-поля и формат дат. Тип TypeScript сам по себе не проверяет JSON во время выполнения.

## Хочешь добавить авторизацию?

Формы входа и регистрации размещай в views, запросы — в api, общее состояние сессии — в stores. Проверки переходов между страницами настрой в router/index.ts после реализации сессии.

Скрытие кнопок и защита маршрута на клиенте улучшают интерфейс, но права доступа обязательно проверяет backend. Способ хранения и обновления токенов согласуй с сервером до реализации refresh token.

## Хочешь добавить диаграмму или отчёт?

Страницу отчёта размещай в views, диаграмму — в components, получение отчёта — в api/progress.ts. Взвешенный прогресс рассчитывает backend; клиент показывает результат.

Кнопку печати можно связать с window.print() и стилями @media print. Экспорт PDF согласуй отдельно: печать браузера с сохранением в PDF и генерация PDF сервером — разные сценарии. Библиотека диаграмм и экспорт сейчас не подключены.

## Хочешь добавить изображения или стили?

`public/` подходит для статических файлов, которые должны копироваться без обработки Vite, например favicon.ico. Импортируемые изображения и общие стили можно размещать в создаваемом `src/assets/`. Для общих стилей добавь импорт в main.ts; для локальных используй style scoped в компоненте.

В импортах `@` означает `src/`: это настроено в vite.config.ts.

## Хочешь добавить тест?

Используй Vitest и Vue Test Utils. Пример — `src/__tests__/App.spec.ts`. При замене стартовой страницы обнови этот тест: сейчас он ожидает текст You did it!.

Проверяй поведение: отправку формы, показ ошибок, сроки и статусы задач, отображение прогресса. UI-тест не заменяет серверную проверку ролей и расчётов.

## Какие команды использовать?

Все команды выполняются из frontend:

| Команда | Назначение |
| --- | --- |
| `npm install` | Установить зависимости; обновления lock-файла проверяй перед коммитом |
| `npm ci` | Установить зависимости по существующему согласованному package-lock.json |
| `npm run dev` | Запустить разработку; адрес напечатает Vite |
| `npm run type-check` | Проверить TypeScript |
| `npm run test:unit -- --run` | Выполнить тесты один раз |
| `npm run build` | Проверить типы и собрать приложение |
| `npm run preview` | Просмотреть собранное приложение |
| `npm run lint` | Запустить линтеры с автоматическим исправлением |
| `npm run format` | Переформатировать src |

Коммить исходники, настройки и package-lock.json. Не коммить node_modules, dist и локальные .env. После lint и format просматривай diff: эти команды изменяют файлы.
